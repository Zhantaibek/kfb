# Инструкция для Strix: сайт Кыргызской фондовой биржи (KSE)

## Цель и область
- Код: этот репозиторий — Next.js 16 (`frontend/`), Express 5 + Prisma + PostgreSQL (`backend/`), общие типы (`shared/`).
- Живой экземпляр (только локальный, тестовые данные): сайт http://host.docker.internal:3000, API через тот же адрес (`/api/...` проксируется на backend).
- ВНЕ области: https://kse.kg, oi.kse.kg и любые другие внешние хосты (backend сам ходит на kse.kg за котировками — его не атаковать), YouTube/Vimeo.

## Что важно для модели угроз
- Вход только для сотрудников (роли admin, editor). Публичных учётных записей нет.
  Тестовая учётная запись локальной базы: admin@kse.kg / admin (только разработка).
- Сессия — подписанная HMAC cookie `kse-admin`. Все `/api/admin/*` должны требовать сессию; `users` — только admin.
- Недоверенный ввод: формы заявок `/api/public/request`, `/api/public/visit`, вход, весь CMS-контент от редакторов
  (HTML новостей и страниц очищается sanitize-html на сервере и выводится через dangerouslySetInnerHTML), загрузки файлов,
  вложения новостей, ссылки и встроенное видео (разрешены только YouTube/Vimeo).
- Внешние API: синхронизация с kse.kg и необязательные ISSUERS_API_URL / LISTING_API_URL (адреса задаёт только .env).

## Приоритеты
1. Обход авторизации / повышение прав редактора до админа, IDOR в `/api/admin/*`.
2. Хранимый XSS через CMS (новости, страницы, настройки, меню), включая обход sanitize-html, ссылки и iframe.
3. Загрузка файлов: подмена типа, обход проверок, обход путей.
4. Открытые редиректы, CSRF, ограничение попыток входа, заголовки безопасности.

## Правила
- Не удалять и не перезаписывать существующие данные массово; создаваемые тестовые записи помечать префиксом `STRIX-TEST`.
- Без нагрузочных и DoS-проверок.
